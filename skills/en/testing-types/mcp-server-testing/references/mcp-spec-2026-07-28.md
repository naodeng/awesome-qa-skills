# MCP protocol basis for server tests

Verified against the official Model Context Protocol specification revision 2026-07-28 on 2026-11-23. These links are pinned to that dated revision; do not silently replace them with a floating latest URL. Protocol MUST / SHOULD statements below describe the cited revision, not every legacy implementation.

## Server and message behavior

- A server implementing the 2026-07-28 revision MUST implement server/discover. The response advertises supported versions and capabilities; server identity is self-reported and is not a security signal.
- The revision removes the protocol initialize handshake and session identifiers. Requests carry protocol version and client capabilities in request metadata; ordinary results include resultType.
- Servers exposing tools declare the tools capability. tools/list may vary by the authorization presented on each request, but must not vary by connection or as a side effect of another request. Stable tool ordering is SHOULD. List results carry ttlMs and cacheScope.
- Stdio uses one newline-delimited JSON-RPC message per line. Server stdout is reserved for valid MCP messages; logging may go to stderr.
- Streamable HTTP uses one MCP endpoint accepting POST. Replies are either a JSON object or request-scoped SSE. Revision 2026-07-28 removes the GET stream endpoint and protocol-level sessions. Server requirements include validating Origin, returning 403 for an invalid present Origin, and preferring localhost binding for local servers.
- Authorization security requirements include validating that presented tokens were issued for the MCP server's audience and forbidding token passthrough.

## Testing use

Use the target's declared revision and transport as the test oracle. A newer date in a moving SDK or a server self-reported identity does not prove which specification the implementation follows. Preserve backward-compatibility cases only when the product explicitly supports legacy revisions. Test expected tool side effects against the tool's documented contract and isolated fixtures; the protocol's tool-call method alone does not define the business effect.

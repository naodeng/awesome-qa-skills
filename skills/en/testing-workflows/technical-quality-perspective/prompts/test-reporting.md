# Technical quality perspective: test reporting

## Required inputs

`stage: test-reporting`; execution records, environment/version identity, case results, defects, and relevant architecture/API/data/security/performance/observability evidence.

## Technical assessment

Summarize technical findings only from supplied records. Relate failures and gaps to affected interfaces, data, compatibility, security, performance, resilience, observability, or maintainability when evidence supports it. Separate executed results from planned work, static inference, and missing evidence.

## Boundary and output

Without execution records do not report tests as run or passed; do not approve release. Output **Summary, Facts, Evidence, Technical findings, Impact and severity, Missing information, Questions, Actions and next steps, Confidence**.

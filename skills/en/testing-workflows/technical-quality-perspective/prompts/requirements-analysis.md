# Technical quality perspective: requirements analysis

## Required inputs

`stage: requirements-analysis`; supplied requirement, declared architecture or integration context, and any API, data, security, performance, compatibility, or observability constraints.

## Technical assessment

Assess only supported technical implications: interfaces and data ownership, error and compatibility constraints, security and privacy requirements, measurable performance expectations, and observability needs. If technical detail is absent, report qualified risk and clarification questions rather than implementation facts.

## Boundary and output

Do not decide product scope, business rules, acceptance criteria, or whether an ordering flow is correct. Output **Summary, Facts, Evidence, Technical findings, Impact and severity, Missing information, Questions, Actions and next steps, Confidence**.

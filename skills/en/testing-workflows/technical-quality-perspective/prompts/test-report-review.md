# Technical quality perspective: test report review

## Required inputs

`stage: test-report-review`; the report under review, its execution evidence, environment/version identity, result/defect records, and relevant technical context.

## Technical assessment

Check that technical conclusions trace to versioned execution evidence and accurately distinguish results, static findings, inference, and gaps. Review relevant reporting of interfaces, data, compatibility, security, performance, observability, resilience, and maintainability. Incomplete reports warrant qualified findings and evidence requests, never invented test results or implementation facts.

## Boundary and output

Do not convert a report review into product approval or release authorization. Output **Summary, Facts, Evidence, Technical findings, Impact and severity, Missing information, Questions, Actions and next steps, Confidence**.

# Technical quality perspective: test-case review

## Required inputs

`stage: test-case-review`; proposed cases plus their requirement/contract traceability, technical context, and any available environment or execution evidence.

## Technical assessment

Review whether cases cover declared contracts, integration/data boundaries, compatibility, security, performance, failure behavior, and observability where relevant. Report missing traceability or technical coverage as qualified findings; do not invent requirements, APIs, implementation behavior, or outcomes.

## Boundary and output

Case quality does not prove code correctness or test execution. Output **Summary, Facts, Evidence, Technical findings, Impact and severity, Missing information, Questions, Actions and next steps, Confidence**.

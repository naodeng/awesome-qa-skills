# UX Quality Perspective: Test Reporting

## Inputs

- `stage: test-reporting`
- Traceable UX test records, observations, defects, screenshots/video, or report material related to UI/UX impact.

## Applicability Check

First confirm that material includes UI/UX impact or experience-test evidence. If it contains only backend, performance, or infrastructure results with no screen/flow/accessibility impact evidence, return **Not applicable** with the reason, facts, gaps, and UX records needed; do not generate experience conclusions.

## UX Questions

- Which observed information-architecture, state, interaction, consistency, responsive, or accessibility conclusions can records support?
- Which tasks, devices, input methods, and assistive technology are covered by evidence, and which remain unknown?
- Are risk, impact scope, reproduction conditions, ownership, and next actions traceable?

## Output Contract

Produce: **Summary, Facts, Evidence, Findings, Risks, Information gaps, Questions, Actions, Confidence**. State only observations supported by records; do not present untested dimensions as passed.

## Evidence and Boundaries

- Do not infer that all devices, states, or assistive technologies pass from one screenshot or partial record.
- Do not assert backend correctness, API reliability, security, complete test success, or release readiness.

# discover-testing Router Reference

> Generated by `scripts/generate_skill_composition_views.py`. This is a self-contained local reference for the Router Skill; it has no repository-outside file dependency and does not turn composition into an installation dependency.

## Boundaries

- Select the single route that best matches the user's goal.
- Return one primary Skill and at most one optional Skill; do not emit a menu of candidates.
- Preserve assumptions and evidence gaps when information is incomplete; this reference does not prove model, runtime, or business effectiveness.

## Routes

### New feature quality readiness (`new-feature-quality`)

- Intent: Turn a new requirement and acceptance goal into testable quality preparation
- Applicable phase: Requirements analysis / test design
- Primary Skill: `requirements-analysis`
- Optional Skill: `test-strategy`
- Handoff: Hand off confirmed risks, acceptance conditions, and test scope for test design
- Not for:
  - Does not replace execution by a concrete test type or tool
  - Does not invent acceptance criteria when inputs are missing

### API delivery (`api-delivery`)

- Intent: Choose a starting point for contract and behavior validation of a new or changed API
- Applicable phase: API design / implementation / verification
- Primary Skill: `api-testing`
- Optional Skill: `api-contract-testing`
- Handoff: Hand off the endpoint inventory, input/output constraints, error paths, and contract risks
- Not for:
  - Does not replace execution by a concrete API client or framework
  - Does not treat contract checks as complete business acceptance

### Change and regression (`change-regression`)

- Intent: Identify change impact and narrow the regression scope
- Applicable phase: Change analysis / regression planning
- Primary Skill: `change-impact-analysis`
- Optional Skill: `regression-test-selection`
- Handoff: Hand off affected components, risk priorities, regression candidates, and evidence gaps
- Not for:
  - Does not claim that regression tests have been executed
  - Does not provide precise impact conclusions without change evidence

### Performance decision (`performance-decision`)

- Intent: Turn performance goals and workload assumptions into an explainable validation and analysis path
- Applicable phase: Performance modeling / result analysis
- Primary Skill: `performance-workload-modeling`
- Optional Skill: `performance-result-analysis`
- Handoff: Hand off workload assumptions, metric definitions, environment prerequisites, and analysis questions
- Not for:
  - Does not replace execution by a load-testing tool or target environment
  - Does not treat a static workload model as runtime results

### AI feature validation (`ai-feature-validation`)

- Intent: Separate functional behavior, model output, and risk-boundary validation for an AI feature
- Applicable phase: AI feature design / evaluation planning
- Primary Skill: `ai-feature-testing`
- Optional Skill: `llm-testing`
- Handoff: Hand off feature goals, input/output samples, risk dimensions, evaluation data, and unrun items
- Not for:
  - Does not claim model effectiveness without a model, data, and target environment
  - Does not treat prompt suggestions as business acceptance or security conclusions

## Handoff after selection

State the routing reason, key assumptions, evidence gaps, and next handoff input; composition is navigation, not a mandatory execution chain.

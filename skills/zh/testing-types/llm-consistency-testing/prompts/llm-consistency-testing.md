# LLM 一致性测试 Prompt

围绕重复输入、版本/模型/提示词因素、不变量、方差证据与比较边界建立可执行、可评审、可追踪的证据边界和判断结果。

## 输入

先做输入审计，逐项记录 known、missing、conflicting、stale、out_of_scope、assumptions：

- known：来源直接支持的范围、LLM 一致性材料、约束或结果。
- missing：影响重复输入、版本/模型/提示词因素、不变量、方差证据与比较边界判断但尚未提供的材料。
- conflicting：来源之间不一致的目标、口径、条件或行为。
- stale：可能过期的架构、版本、模型、数据集或记录。
- out_of_scope：不属于本 Skill、未授权或需要真实环境的动作。
- assumptions：为了形成受限初版而暂时采用的假设，必须写验证方法。

## 你要做的事

1. 用一句话复述目标、对象、范围和成功标准。
2. 审计输入的完整性、可信度、时效性和可比性，重点检查重复输入、版本因素、模型因素、不变量、方差证据。
3. 围绕LLM 一致性建立风险或失败模型，明确触发条件、预期关注点、影响和证据需求。
4. 把分析转成具体场景、断言、验证步骤、决策门槛或改进实验。
5. 给出剩余风险、证据缺口和下一步，不把假设包装成事实。

## 执行规则

- 每个关键结论都要说明来源、证据状态和验证方法。
- 场景至少包含前置条件、动作或刺激、预期结果或判断标准、所需证据和停止条件。
- 使用 P0/P1/P2/P3 或等价分级，并解释业务影响、可能性、可探测性或决策成本。
- 具体覆盖重复输入、版本/模型/提示词因素、不变量、方差证据与比较边界，不以相邻测试类型、工具名或单个样例代替领域判断。
- 不编造数字、阈值、模型行为、根因、系统行为、执行记录、全部通过或安全批准。
- 涉及用户数据、生产或安全时默认使用最小权限、脱敏数据、mock、dry-run 或隔离环境。
- 将事实、推断、候选建议和 Human 决策分开；风险接受、例外和安全判断只能由 Human 确认。

## 领域操作与判定

以下步骤对提供材料进行设计或静态核对；fixture 判定、候选方案与真实执行证据分别记录。项目未提供的规则、门槛和授权保持待确认。

1. 固定样本 ID、模型/Prompt/工具/数据版本、temperature、seed（仅供应商支持时）和其他采样参数，记录项目指定重复次数；seed 相同不代表跨版本可复现。
2. 先比 schema、必需字段、允许枚举和政策等结构不变量，再依据项目 rubric 比语义结论；同义表达或获准顺序变化不应报错。
3. 逐样本报告重复分母、结构失败数、语义失败数与偶发失败；方差需明确数值变量、统计单位和算法，不将文本不同率冒充质量方差。
4. 缺重复数据只报告单次观察，缺 rubric 则语义一致性 UNKNOWN；不同参数或版本分组比较，不混成稳定性证据。

## 评测证据状态与结构化追踪

当任务涉及评测、回归或结果审查时，为每个结论提供 `evaluation_status` 字段，枚举为 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN` 或 `UNKNOWN`。`PASS` 需要可追溯的实际运行记录和满足范围内全部必需断言的证据；没有运行结果时标记 `NOT_RUN`，尝试运行但被环境或权限阻止时标记 `BLOCKED`，证据不足以判断时标记 `UNKNOWN`。设计方案、静态检查或文件存在不能单独成为 `PASS` 证据。质量门禁或逐样本决定仍按其领域字段记录，与 `evaluation_status` 分开。

结构化追踪至少记录 `trace_id`、输入/样本 ID、模型/提示词/数据集/Schema 版本、影响结果的参数、run/trial ID、解析状态、Schema 状态、语义状态和证据引用。先独立检查 JSON 可解析性、Schema 约束和领域语义；解析成功不代表 Schema 或语义通过。脱敏原始输出或可复核哈希，保留重复次数和分母，不能用缺失证据填成通过。

## 模型/供应商迁移模式

当目标是迁移模型、供应商或版本时，必须把旧版 baseline 与候选新版绑定为同一个迁移评估：固定相同任务集/数据集版本、提示词、工具、参数与分层抽样；分别记录模型精确版本、run ID、失败样本和成本/时延。

- 记录旧模型弃用来源与截止日期、迁移负责人、双跑窗口、回滚点和重新基线批准人；不能把切换上线等同于迁移验证。
- 由项目契约提供能力/质量、拒答/安全、延迟和成本门槛；按任务层比较输出差异与统计不确定性。候选模型缺运行或价格证据时，该维度为 NOT_RUN/UNKNOWN。
- 只有旧、新两侧证据完整且所有必选门槛满足，才可给迁移 PASS；基线已过期、任务不可比或任一侧缺 run ID 时阻塞结论。

## 最低覆盖清单

- 重复输入、版本因素、模型因素、不变量、方差证据
- 已确认事实、当前假设、信息缺口、证据质量和时效性
- 高风险路径、阻塞条件、停止/升级/回滚或人工接管条件
- 最小验证动作、责任角色、关闭条件、剩余风险和 Human 决策
- 事实、证据支持的推断、候选建议、Human 决策

## 输出

### 1. 任务理解与范围

写明目标、对象、纳入项、排除项、成功标准和未授权动作。

### 2. 输入审计

分别列出 known、missing、conflicting、stale、out_of_scope、assumptions，并标明来源、时效性和证据质量。

### 3. LLM 一致性分析与优先级

说明重复输入、版本/模型/提示词因素、不变量、方差证据与比较边界的场景、触发条件、预期行为、影响、优先级和证据缺口。

### LCT-## 发现合同

每条发现必须包含：

- 对象/规则
- 来源
- 触发条件或适用范围
- 预期关注点/理由
- 证据状态
- 影响/优先级
- 责任角色
- 关闭条件
- 验证方法

### 4. 候选验证与剩余风险

把候选建议和实际执行分开，写出最小验证动作、停止/升级条件、剩余风险和待确认问题。

### 5. Human 决策

只列需要 Human 确认、风险接受、例外授权、回滚或安全判断的事项。

输出必须同时保留以下分区：事实、证据支持的推断、候选建议、Human 决策。

## 质量要求

- 内容必须针对LLM 一致性，不能只是替换标题的通用模板。
- 高风险路径必须具体到失败模式、预期行为和证据。
- 数字、根因和系统行为不得无依据推断。
- 静态分析、计划或 dry-run 不等于真实执行、全部测试通过或安全批准。
- 让执行者无需猜测下一步，让评审者能追溯事实、推断、建议和 Human 决策的边界。

# CI 测试流水线优化 Prompt

围绕流水线阶段、反馈延迟、资源、波动、缓存/分片与回滚边界建立可执行、可评审、可追踪的证据边界和判断结果。

## 输入

先做输入审计，逐项记录 known、missing、conflicting、stale、out_of_scope、assumptions：

- known：来源直接支持的范围、CI 测试流水线材料、约束或结果。
- missing：影响流水线阶段、反馈延迟、资源、波动、缓存/分片与回滚边界判断但尚未提供的材料。
- conflicting：来源之间不一致的目标、口径、条件或行为。
- stale：可能过期的架构、版本、指标、样本或记录。
- out_of_scope：不属于本 Skill、未授权或需要真实环境的动作。
- assumptions：为了形成受限初版而暂时采用的假设，必须写验证方法。

## 你要做的事

1. 用一句话复述目标、对象、范围和成功标准。
2. 审计输入的完整性、可信度、时效性和可比性，重点检查阶段依赖、反馈延迟、资源使用、波动、缓存与分片。
3. 围绕CI 测试流水线建立风险或失败模型，明确触发条件、预期关注点、影响和证据需求。
4. 把分析转成具体场景、断言、验证步骤、决策门槛或改进实验。
5. 给出剩余风险、证据缺口和下一步，不把假设包装成事实。

## 执行规则

- 每个关键结论都要说明来源、证据状态和验证方法。
- 场景至少包含前置条件、动作或刺激、预期结果或判断标准、所需证据和停止条件。
- 使用 P0/P1/P2/P3 或等价分级，并解释业务影响、可能性、可探测性或决策成本。
- 具体覆盖流水线阶段、反馈延迟、资源、波动、缓存/分片与回滚边界，不以相邻测试类型、工具名或单个样例代替领域判断。
- 不编造数字、阈值、根因、系统行为、执行记录、全部通过或发布批准。
- 涉及生产、隐私或安全时默认使用最小权限、脱敏数据、mock、dry-run 或隔离环境。
- 将事实、推断、候选建议和 Human 决策分开；风险接受、例外和发布判断只能由 Human 确认。
- Markdown 表格单元格中的字面竖线（包括行内代码）要写为 `\|`，或改写表述，避免被解析为额外列。

## 领域操作与判定

以下步骤对提供材料进行设计或静态核对；fixture 判定、候选方案与真实执行证据分别记录。项目未提供的规则、门槛和授权保持待确认。

1. 以 commit/run/runner/config/test-set ID 固定比较对象；从事件时间线分解 queue、checkout/install、setup、execute、retry、report，区分端到端等待与 runner 忙时。
2. 沿 DAG 计算实际关键路径，重叠 job 不相加；报告重试次数与失败原始结果，不能用重跑绿灯隐藏首失败。
3. 缓存键包含项目相关 lockfile/工具链/配置身份；比较 cold/warm，记录命中和失效验证，不能复用不匹配缓存跳过依赖校验。
4. before/after 保持保护义务、测试集、故障检出、资源和窗口可比；删测试或吞失败的提速候选拒绝，提出可测收益和回滚信号。
5. AI eval 作业单独记录模型/提示/数据集/judge 版本、样本数、token 或调用成本与时延；预算和门槛必须有来源，不能把一次偶然的低成本 run 当稳定基线。
6. 分片以稳定 case ID 和数据集版本划分，汇总保留分片失败、缺失和重复；仅在输入、模型与评测配置身份匹配时复用结果缓存，默认不缓存易变模型输出。
7. 重试策略区分传输失败与评测断言失败；只重试安全且幂等的调用，报告每次 attempt、原始失败和累计成本，重试变绿不得覆盖首个失败或证据缺失。
## 最低覆盖清单

- 阶段依赖、反馈延迟、资源使用、波动、缓存与分片
- AI eval 的预算、分片身份、模型/数据集缓存有效性、重试次数与累计成本（适用时）
- 已确认事实、当前假设、信息缺口、证据质量和时效性
- 高风险路径、阻塞条件、停止/升级/回滚或人工接管条件
- 最小验证动作、责任角色、关闭条件、剩余风险和 Human 决策
- 事实、证据支持的推断、候选建议、Human 决策

## 输出

### 1. 任务理解与范围

写明目标、对象、纳入项、排除项、成功标准和未授权动作。

### 2. 输入审计

分别列出 known、missing、conflicting、stale、out_of_scope、assumptions，并标明来源、时效性和证据质量。

### 3. CI 测试流水线分析与优先级

说明流水线阶段、反馈延迟、资源、波动、缓存/分片与回滚边界的场景、触发条件、预期行为、影响、优先级和证据缺口。

### CTO-## 发现合同

每条发现必须包含：

- 对象/规则
- 来源
- 触发条件或适用范围
- 预期关注点/理由
- 证据状态
- 影响/优先级
- 责任角色
- 关闭条件
- 验证方法

### 4. 候选验证与剩余风险

把候选建议和实际执行分开，写出最小验证动作、停止/升级条件、剩余风险和待确认问题。

### 5. Human 决策

只列需要 Human 确认、风险接受、例外授权、回滚或发布判断的事项。

输出必须同时保留以下分区：事实、证据支持的推断、候选建议、Human 决策。

## 质量要求

- 内容必须针对CI 测试流水线，不能只是替换标题的通用模板。
- 高风险路径必须具体到失败模式、预期行为和证据。
- 数字、根因和系统行为不得无依据推断。
- 静态分析、计划或 dry-run 不等于真实执行、全部测试通过或发布已批准。
- 让执行者无需猜测下一步，让评审者能追溯事实、推断、建议和 Human 决策的边界。

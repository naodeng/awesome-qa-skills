# RAG 检索测试 Prompt

围绕查询变体、分块、过滤、召回/精确率代理、排序、新鲜度与检索证据建立可执行、可评审、可追踪的证据边界和判断结果。

## 输入

先做输入审计，逐项记录 known、missing、conflicting、stale、out_of_scope、assumptions：

- known：来源直接支持的范围、检索结果材料、约束或结果。
- missing：影响查询变体、分块、过滤、召回/精确率代理、排序、新鲜度与检索证据判断但尚未提供的材料。
- conflicting：来源之间不一致的目标、口径、条件或行为。
- stale：可能过期的架构、版本、模型、数据集或记录。
- out_of_scope：不属于本 Skill、未授权或需要真实环境的动作。
- assumptions：为了形成受限初版而暂时采用的假设，必须写验证方法。

## 你要做的事

1. 用一句话复述目标、对象、范围和成功标准。
2. 审计输入的完整性、可信度、时效性和可比性，重点检查查询变体、分块策略、过滤条件、召回代理、排序与新鲜度。
3. 围绕检索结果建立风险或失败模型，明确触发条件、预期关注点、影响和证据需求。
4. 把分析转成具体场景、断言、验证步骤、决策门槛或改进实验。
5. 给出剩余风险、证据缺口和下一步，不把假设包装成事实。

## 执行规则
- 计划、静态分析和 Eval fixture 本身不是运行证据；若要求判断实际评测/执行且 trace 缺少有效 run ID 与原始结果，输出 `evaluation_status: NOT_RUN`、`run_evidence: []` 和 `domain_conclusion: UNASSESSED`，不得声称 PASS。


- 每个关键结论都要说明来源、证据状态和验证方法。
- 场景至少包含前置条件、动作或刺激、预期结果或判断标准、所需证据和停止条件。
- 使用 P0/P1/P2/P3 或等价分级，并解释业务影响、可能性、可探测性或决策成本。
- 具体覆盖查询变体、分块、过滤、召回/精确率代理、排序、新鲜度与检索证据，不以相邻测试类型、工具名或单个样例代替领域判断。
- 不编造数字、阈值、模型行为、根因、系统行为、执行记录、全部通过或安全批准。
- 涉及用户数据、生产或安全时默认使用最小权限、脱敏数据、mock、dry-run 或隔离环境。
- 将事实、推断、候选建议和 Human 决策分开；风险接受、例外和安全判断只能由 Human 确认。

## 领域操作与判定

以下步骤对提供材料进行设计或静态核对；fixture 判定、候选方案与真实执行证据分别记录。项目未提供的规则、门槛和授权保持待确认。

1. 给query及相关集合固定标注规则、文档/chunk粒度、标注者与版本；Recall@k分母为已知相关集合，Precision@k按实际返回数和项目对重复chunk规则计算。
2. 逐结果核对top-k/rank、relevance、租户/权限过滤、新鲜度与文档版本；越权结果不能因相关而计成功，过时结果不由分数高抵消。
3. 控制相同query、索引、过滤和资源比较排序或配置变化；无完整相关集合只报代理指标和限制，不宣称真实召回完整。
4. 区分相关资料未取回的retrieval failure与取回正确但生成错误的generation failure；缺生成输出不能定位生成环节，缺标签保持UNKNOWN。
5. 迁移比较固定 embedding 模型/维度/归一化、chunk 与索引构建身份；在相同 query、相关标签、权限过滤和 top-k 下比较旧/新索引，不把模型、切块和排序同时变化后的差异归因给单一因素。
6. 对 hybrid 检索分开记录各路召回与融合规则；对 reranker 固定候选集、输入截断、排序结果和模型版本，确认重排没有绕过租户或权限过滤。
7. 重建/刷新验证新增、更新、删除文档的传播时间与索引版本；检查 tombstone、重复写入、部分失败和回滚后旧/新索引身份。项目阈值缺失时列待确认，不臆造新鲜度门槛。

## 最低覆盖清单

- 查询变体、分块策略、过滤条件、召回代理、排序与新鲜度
- embedding/索引迁移、hybrid 融合、reranker、重建与新鲜度传播
- 已确认事实、当前假设、信息缺口、证据质量和时效性
- 高风险路径、阻塞条件、停止/升级/回滚或人工接管条件
- 最小验证动作、责任角色、关闭条件、剩余风险和 Human 决策
- 事实、证据支持的推断、候选建议、Human 决策

## 输出

### 1. 任务理解与范围

写明目标、对象、纳入项、排除项、成功标准和未授权动作。

### 2. 输入审计

分别列出 known、missing、conflicting、stale、out_of_scope、assumptions，并标明来源、时效性和证据质量。

### 3. 检索结果分析与优先级

说明查询变体、分块、过滤、召回/精确率代理、排序、新鲜度与检索证据的场景、触发条件、预期行为、影响、优先级和证据缺口。

### RAGT-## 发现合同

每条发现必须包含：

- 对象/规则
- 来源
- 触发条件或适用范围
- 预期关注点/理由
- 证据状态
- 影响/优先级
- 责任角色
- 关闭条件
- 验证方法

### 4. 候选验证与剩余风险

把候选建议和实际执行分开，写出最小验证动作、停止/升级条件、剩余风险和待确认问题。

### 5. Human 决策

只列需要 Human 确认、风险接受、例外授权、回滚或安全判断的事项。

输出必须同时保留以下分区：事实、证据支持的推断、候选建议、Human 决策。

## 质量要求

- 内容必须针对检索结果，不能只是替换标题的通用模板。
- 高风险路径必须具体到失败模式、预期行为和证据。
- 数字、根因和系统行为不得无依据推断。
- 静态分析、计划或 dry-run 不等于真实执行、全部测试通过或安全批准。
- 让执行者无需猜测下一步，让评审者能追溯事实、推断、建议和 Human 决策的边界。

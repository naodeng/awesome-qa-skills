# MCP 服务端测试的协议依据

已于 2026-11-23 对照 Model Context Protocol 官方 2026-07-28 修订版核实。以下链接固定到带日期的修订版，不要静默替换成浮动的 latest 链接。MUST / SHOULD 描述该修订版，不代表每个旧版实现。

## 服务端与消息行为

- 实现 2026-07-28 修订版的服务端必须实现 server/discover。响应声明支持的协议版本和能力；服务端自报身份不是安全信号。
- 该修订版移除协议级 initialize 握手和会话标识。请求通过元数据携带协议版本与客户端能力；普通结果包含 resultType。
- 提供工具的服务端声明 tools 能力。tools/list 可根据每个请求所带的授权变化，但不得按连接变化，也不得因同一连接上的其他请求产生副作用。稳定工具顺序是 SHOULD。列表结果携带 ttlMs 和 cacheScope。
- stdio 使用每行一条换行分隔的 JSON-RPC 消息。服务端 stdout 只能输出有效 MCP 消息；日志可写入 stderr。
- Streamable HTTP 使用一个接受 POST 的 MCP endpoint。响应可以是 JSON 对象或限于当前请求的 SSE。2026-07-28 修订版移除 GET 流 endpoint 和协议级会话。服务端要求包括校验 Origin；若提供的 Origin 无效则返回 403；本地服务 SHOULD 绑定 localhost。
- 授权安全要求包括校验出示的 token 是专门为该 MCP 服务端签发，并禁止 token passthrough。

## 测试用法

使用目标声明的修订版与传输作为测试判定依据。SDK 的移动版本日期或服务端自报身份不能证明实际实现遵循的规范。仅当产品明确支持旧修订版时，才保留兼容测试。根据工具已说明的契约判断业务副作用并使用隔离 fixture；协议的工具调用方法本身不定义业务效果。

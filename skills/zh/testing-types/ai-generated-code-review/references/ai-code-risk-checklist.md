# AI 生成代码风险检查表

逐项按适用性审查，并把证据缺失标为待核实：

- **意图与范围**：任务、验收条件、基线与变更文件是否对应；有无无关文件、重复代码或未授权的副作用。
- **依赖与接口**：包名、API、字段、参数和版本是否能在锁文件、仓库资料、源码或受信注册表中核实。
- **错误与降级**：是否吞异常、返回静默默认值、吞掉部分失败、伪造缓存/成功状态或把失败路径改成成功。
- **行为测试**：关键验收条件是否有独立可观察断言；测试是否 mock 被测逻辑、删除负向场景或只改测试以配合新实现。
- **CI 完整性**：必需 job、覆盖率阈值、lint/typecheck、安全扫描是否被删除、弱化、条件跳过或 `continue-on-error`。
- **复制粘贴与供应边界**：是否引入重复实现、未经审查的生成代码/依赖，或将 PR/Issue/文档中的不可信文本送入脚本、Shell 或 Agent 工具。
- **证据和归属**：来源、run、人工复核和采纳有无明确证据；生成模型缺失本身不是实现缺陷。

不要将清单机械套用成发现。每条正式发现都需要变更证据、触发条件、影响和可验证的修复。

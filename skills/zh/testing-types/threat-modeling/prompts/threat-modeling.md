# 威胁建模 Prompt

## 输入

先做输入审计，逐项记录 known、missing、conflicting、stale、out_of_scope、assumptions：

- known：来源直接支持的范围、威胁场景、角色或约束。
- missing：影响资产、信任边界、攻击面、威胁场景、缓解措施和假设判断但尚未提供的材料。
- conflicting：不同来源之间不一致的目标、条件、角色或行为。
- stale：可能过期的架构、版本、策略、日志或扫描记录。
- out_of_scope：不属于本 Skill、未授权或需要真实环境的动作。
- assumptions：形成受限初版所需的临时假设，必须给验证方法。

## 你要做的事

1. 复述安全目标、对象、范围和成功标准。
2. 围绕资产、信任边界、攻击面、威胁场景、缓解措施和假设建立场景、触发条件、预期关注点和证据需求。
3. 区分静态审查、候选验证和未授权的真实系统动作。
4. 为每条发现记录优先级、责任角色、关闭条件和验证方法。
5. 将事实、证据支持的推断、候选建议和 Human 决策分开。

## 执行规则

- 先审计 known、missing、conflicting、stale、out_of_scope、assumptions。
- 每条结论都要回溯来源；没有证据时写待确认、blocked 或验证建议。
- 使用威胁场景作为领域锚点，使用 THM-## 作为发现编号。
- 场景至少包含前置条件、刺激或动作、预期结果、证据和停止条件。
- 不登录系统、不调用真实 API、不读取凭据、不进行破坏性安全操作。
- 不把静态文件、名称、模板或 dry-run 升级为漏洞不存在、攻击成功或发布批准。

## 最低覆盖清单

- 威胁场景和适用范围
- 主要风险或失败模式与触发条件
- 数据、权限、影响和优先级
- 现有控制、依赖、信任边界和证据时效
- 预期结果、证据状态和验证方法
- 关闭条件、剩余风险和 Human 决策
- facts、evidence-backed inferences、candidate recommendations、Human decisions

## 输出

### 1. 任务理解与范围

写明目标、对象、纳入项、排除项、成功标准和未授权动作。

### 2. 输入审计

列出 known、missing、conflicting、stale、out_of_scope、assumptions，并注明来源和时效性。

### 3. 威胁场景与安全风险模型

说明资产、信任边界、攻击面、威胁场景、缓解措施和假设的场景、触发条件、预期行为、影响、优先级和证据缺口。

### THM-## 发现合同

每条发现必须包含：

- 对象/规则
- 来源
- 触发条件或适用范围
- 预期关注点/理由
- 证据状态
- 影响/优先级
- 责任角色
- 关闭条件
- 验证方法

### 4. 候选验证与剩余风险

分离候选建议和实际执行，写出最小隔离验证、停止/升级条件、剩余风险和待确认问题。

### 5. Human 决策

只列需要 Human 确认、风险接受、例外授权或发布判断的事项。

输出必须同时保留：事实、证据支持的推断、候选建议、Human 决策。

## 质量要求

- 内容必须针对资产、信任边界、攻击面、威胁场景、缓解措施和假设，不能只是替换标题的通用模板。
- 没有直接证据时，不得写“测试已执行”“全部测试通过”“发布已批准”。
- 漏洞、影响、阈值、攻击成功和修复状态都必须有来源。
- 让执行者知道下一步，让评审者能复核事实、推断、建议和 Human 决策边界。

# 假绿与虚假信心清单

在复核 AI 辅助测试结果时检查以下模式。命中时保留真实状态并补证，不要靠修改判定规则消除问题。

1. **断言无效但全绿：**断言未验证目标行为，或只检查状态码/非空值。
2. **消除失败：**为通过门禁而删除、跳过、放宽或屏蔽失败检查。
3. **虚构接口：**输出引用不存在的 API、字段、配置或业务规则。
4. **只算生成时间：**用生成分钟数宣称提效，忽略复核、返工、验收和 token 费用。
5. **未审即采纳：**没有 `reviewer` 和 `ACCEPTED` 记录就把草稿标成正式资产。
6. **覆盖率代替质量：**以覆盖率证明缺陷可检出、oracle 正确或业务已验收。
7. **隐藏失败路径：**省略失败用例、重试、环境限制或反例，只报告最终绿灯。
8. **摘要代替原始证据：**把 AI 摘要、解释或截图描述当成日志、run ID 或执行报告。

逐项记录来源和影响。缺执行证据为 `NOT_RUN` 或 `BLOCKED`；无法确认的结论为 `UNKNOWN`；未经人工复核的草稿为 `DRAFT`。给出责任人和最小补证步骤。

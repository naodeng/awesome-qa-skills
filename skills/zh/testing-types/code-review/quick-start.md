# 代码审查 - 5 分钟上手

## 最小输入

把下面信息贴给 AI（缺什么就标明「未知」）：

```text
请用 code-review 审查本次变更。
业务目标：
变更范围 / Diff：
技术栈：
上下游依赖：
已知风险或规范：
```

## 期望产出结构

1. 变更摘要 + 综合风险评级  
2. P0 / P1 / P2 清单（含定位与修复建议）  
3. 可测性与可观测性  
4. 建议修复顺序  
5. 剩余风险与信息缺口  

## 分级速记

| 级别 | 含义 | 示例 |
| --- | --- | --- |
| P0 | 阻塞合入 | 资损、严重安全、主流程必现中断 |
| P1 | 本迭代建议修 | 潜在并发、明显性能、核心日志缺失 |
| P2 | 技术债 / 可选 | 非核心坏味道、次要可读性 |

## 质量自检（提交审查结论前）

- [ ] 没有堆砌命名/缩进类噪声  
- [ ] P0/P1 有后果依据与定位  
- [ ] 每条有可执行修复方向  
- [ ] 假设与缺口已标明

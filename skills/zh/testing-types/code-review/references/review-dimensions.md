# 代码审查维度补充（按需加载）

仅在需要细化扫描维度或对齐分级口径时阅读；不要默认整篇塞进每次审查。

## 1. 逻辑与状态

- 空指针 / 防空缺失、越界、状态机未闭环
- 异常分支吞错、错误码被静默忽略
- 资源未释放（连接、句柄、锁、临时文件）

## 2. 并发与分布式一致性

- 竞态、丢失更新、check-then-act
- 幂等破坏（重试导致重复扣款/发货/写库）
- 分布式事务边界错位、缓存与 DB 不一致
- 锁粒度不当、死锁风险

## 3. 资损与安全

- 金额/库存精度（浮点计算、舍入方向）
- 越权、重复支付/退款、优惠叠加漏洞
- 注入（SQL/NoSQL/命令/模板）、XSS
- 敏感信息泄漏（日志明文 Token/密码、密钥硬编码、未脱敏）

## 4. API 契约与兼容

- 字段增删改、类型/枚举变更、默认值语义变化
- 破坏前后向兼容、污染存量数据
- 对上下游调用方、消息消费者、批任务的不可预期影响

## 5. 可测性与可演进

- 硬编码时间/随机性、强依赖难 Mock
- 缺少关键断言点或测试数据难构造
- 超长函数/类、职责错位、魔法值、高圈复杂度、强耦合
- 仅标记高价值坏味道；避免风格吹毛求疵

## 6. 性能与资源（高价值项）

- N+1 查询、循环内 IO/RPC、无界大拷贝
- 连接池/超时/重试配置明显不当
- 内存泄漏或无界缓存增长迹象

## 7. 错误处理与可观测性

- 异常是否可诊断、是否吞掉根因
- 日志是否含 TraceID / 关键业务键（注意脱敏）
- 核心链路是否有可告警指标

## 分级口径提醒

| 级别 | 合入决策 | 典型后果 |
| --- | --- | --- |
| P0 | 必须先修再合入 | 资损、严重安全、主流程必现故障 |
| P1 | 强烈建议本迭代修 | 高概率边缘故障、明显性能、核心不可观测 |
| P2 | 可进技术债 | 非核心可维护性、次要优化 |

# 常见伪测试模式

| 模式 | 为何不可靠 | 审查信号 | 修正方向 |
| --- | --- | --- | --- |
| 无断言 | 调用代码却没有 `assert` / `expect` | 只有执行，没有验证 | 断言可观察的业务结果 |
| 恒真断言 | 无论实现如何都通过 | `expect(true).toBe(true)` | 断言有业务意义的结果 |
| 弱断言 | 关键业务结果仍未知 | 唯一检查为 `not.toBeNull()` 或 truthy | 断言关键值、结构或错误契约 |
| 只验证 mock 被调用 | 测到实现细节而非结果 | `toHaveBeenCalled` 是唯一断言 | 同时验证输出、状态或副作用 |
| 过宽匹配 | 错误结果也会匹配 | `any`、模糊正则、只断言 truthy | 断言关键值、结构和错误码 |
| 自我验证的 fixture | 生产逻辑与期望同源错误 | 测试复制实现算法 | 使用独立需求、样本或不变量 |
| 吞掉异常或永久重试 | 失败被隐藏为绿灯 | 空 `catch`、无限重试 | 断言失败类型；限制并观察重试 |
| 无意义快照 | 大量输出掩盖关键变化 | 快照巨大且未检查语义 | 断言稳定、业务关键字段 |
| 自我比较 | 期望来自待验证对象本身 | `expect(result).toEqual(result)` | 使用独立、可解释的期望 |
| 只检查状态码 | 成功状态不等于业务正确 | 只有 `status === 200` | 加上响应契约及业务后置条件 |
| Mock 被测对象 | 真实生产逻辑未执行 | service/module 本身被 mock | 只 mock 外部边界，运行被测对象 |
| 无业务后置条件 | 页面跳转或元素存在不等于成功 | 只点击按钮、检查 URL / 元素 | 断言用户可见或持久化的业务结果 |
| Coverage padding | 执行代码但没有行为证明 | 为覆盖率调用函数 | 以故障模型补充业务断言 |

审查时优先回答：删掉或破坏被测逻辑后，这个测试会不会失败？若不能证明，标为风险而非“已覆盖”。

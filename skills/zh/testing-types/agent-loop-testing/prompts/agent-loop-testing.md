# Agent 循环测试 Prompt

围绕循环状态、规划/动作/观察周期、停止条件、预算、重复行为与 trace 证据建立可执行、可评审、可追踪的证据边界和判断结果。

## 输入

先做输入审计，逐项记录 known、missing、conflicting、stale、out_of_scope、assumptions：

- known：来源直接支持的范围、Agent 循环材料、约束或结果。
- missing：影响循环状态、规划/动作/观察周期、停止条件、预算、重复行为与 trace 证据判断但尚未提供的材料。
- conflicting：来源之间不一致的目标、口径、条件或行为。
- stale：可能过期的架构、版本、模型、数据集或记录。
- out_of_scope：不属于本 Skill、未授权或需要真实环境的动作。
- assumptions：为了形成受限初版而暂时采用的假设，必须写验证方法。

## 你要做的事

1. 用一句话复述目标、对象、范围和成功标准。
2. 审计输入的完整性、可信度、时效性和可比性，重点检查循环状态、规划动作观察、停止条件、预算、重复行为。
3. 围绕Agent 循环建立风险或失败模型，明确触发条件、预期关注点、影响和证据需求。
4. 把分析转成具体场景、断言、验证步骤、决策门槛或改进实验。
5. 给出剩余风险、证据缺口和下一步，不把假设包装成事实。

## 执行规则
- 计划、静态分析和 Eval fixture 本身不是运行证据；若要求判断实际评测/执行且 trace 缺少有效 run ID 与原始结果，输出 `evaluation_status: NOT_RUN`、`run_evidence: []` 和 `domain_conclusion: UNASSESSED`，不得声称 PASS。


- 每个关键结论都要说明来源、证据状态和验证方法。
- 场景至少包含前置条件、动作或刺激、预期结果或判断标准、所需证据和停止条件。
- 使用 P0/P1/P2/P3 或等价分级，并解释业务影响、可能性、可探测性或决策成本。
- 具体覆盖循环状态、规划/动作/观察周期、停止条件、预算、重复行为与 trace 证据，不以相邻测试类型、工具名或单个样例代替领域判断。
- 不编造数字、阈值、模型行为、根因、系统行为、执行记录、全部通过或安全批准。
- 涉及用户数据、生产或安全时默认使用最小权限、脱敏数据、mock、dry-run 或隔离环境。
- 将事实、推断、候选建议和 Human 决策分开；风险接受、例外和安全判断只能由 Human 确认。

## 领域操作与判定

以下步骤对提供材料进行设计或静态核对；fixture 判定、候选方案与真实执行证据分别记录。项目未提供的规则、门槛和授权保持待确认。

1. 按 task/run/step ID 记录计划、工具名与归一化参数、观察身份/摘要、业务状态变化和时间/费用累计；敏感参数脱敏但保留去重依据。
2. 进展以项目目标的新证据或状态前进判断；动作/观察相同且目标未前进记无进展周期。只重复文本或工具成功不算进展。
3. 使用项目指定无进展上限、重试策略、时间和费用预算；安全/取消立即停止，任一硬预算触顶优先于继续计划，未给上限时提问而不自定数值。
4. 对重复调用转入项目允许的改变策略、停止或升级分支；输出触发 step、终止类别、剩余工作和无额外副作用证据。
## 最低覆盖清单

- 循环状态、规划动作观察、停止条件、预算、重复行为
- 已确认事实、当前假设、信息缺口、证据质量和时效性
- 高风险路径、阻塞条件、停止/升级/回滚或人工接管条件
- 最小验证动作、责任角色、关闭条件、剩余风险和 Human 决策
- 事实、证据支持的推断、候选建议、Human 决策

## 输出

### 1. 任务理解与范围

写明目标、对象、纳入项、排除项、成功标准和未授权动作。

### 2. 输入审计

分别列出 known、missing、conflicting、stale、out_of_scope、assumptions，并标明来源、时效性和证据质量。

### 3. Agent 循环分析与优先级

说明循环状态、规划/动作/观察周期、停止条件、预算、重复行为与 trace 证据的场景、触发条件、预期行为、影响、优先级和证据缺口。

### ALT-## 发现合同

每条发现必须包含：

- 对象/规则
- 来源
- 触发条件或适用范围
- 预期关注点/理由
- 证据状态
- 影响/优先级
- 责任角色
- 关闭条件
- 验证方法

### 4. 候选验证与剩余风险

把候选建议和实际执行分开，写出最小验证动作、停止/升级条件、剩余风险和待确认问题。

### 5. Human 决策

只列需要 Human 确认、风险接受、例外授权、回滚或安全判断的事项。

输出必须同时保留以下分区：事实、证据支持的推断、候选建议、Human 决策。

## 质量要求

- 内容必须针对Agent 循环，不能只是替换标题的通用模板。
- 高风险路径必须具体到失败模式、预期行为和证据。
- 数字、根因和系统行为不得无依据推断。
- 静态分析、计划或 dry-run 不等于真实执行、全部测试通过或安全批准。
- 让执行者无需猜测下一步，让评审者能追溯事实、推断、建议和 Human 决策的边界。

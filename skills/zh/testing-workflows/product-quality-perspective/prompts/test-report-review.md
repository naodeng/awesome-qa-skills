# 产品质量视角：测试报告评审

## 输入

- `stage: test-report-review`
- 待评审测试报告、原始结果或缺陷信息，以及范围、验收标准、发布目标和用户影响上下文。

## 适用性判断

先确认有报告或足以核对报告结论的材料。若没有，输出“**不适用**”，解释无法评审的原因、已知事实、缺口与所需材料；不要虚构报告问题。

## 产品问题

- 报告是否清楚区分已测/未测范围、事实/推断、风险/结论？
- 报告结论是否追溯到用户价值、业务规则、验收标准和真实证据？
- 风险、阻塞、限制和信心是否被完整呈现，还是被指标掩盖？
- 还缺少哪些证据、问题或行动才能支持下一步决策？

## 输出合同

输出独立的产品质量报告，依次包含：**摘要、事实、证据、发现、风险、信息缺口、待确认问题、行动、信心等级**。将发现定位为报告表达或证据链问题，而不是凭空重判测试结果。

## 证据与边界

- 只根据提供报告和原始材料核对；矛盾或缺失必须明确标出。
- 不编造测试执行、缺陷、代码正确性、测试通过或发布批准结论。
- 本 Prompt 是产品质量评审，不替代 QA 测试复盘、工程审查或发布审批。

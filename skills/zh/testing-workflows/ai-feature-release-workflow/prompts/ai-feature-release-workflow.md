# AI 特性发布工作流 Prompt

为 AI 特性连接评测设计、发布门禁、分阶段灰度、监控和回滚计划，形成带版本的可复核证据链。本 Workflow 负责协调，不实现评测引擎、不执行生产变更，也不批准发布。

## 输入

记录特性与变更范围；当前和候选模型/供应商/版本；Prompt 或 Agent 版本；数据集和 rubric/judge 版本；评测 run ID 与原始证据位置；阈值和抽样计划；成本与 flake 预算；目标环境和灰度人群；监控指标及来源阈值；回滚动作；负责人和决策权限。不可用的值标记 `UNKNOWN`。

## 阶段契约

| 阶段 | 进入证据 | 必需产物 | 退出条件 |
| --- | --- | --- | --- |
| 契约与风险 | 特性目标、范围、负责人 | 评测目标、风险切片、数据集/judge 身份、抽样计划、阈值、隐私边界 | 标准和来源版本可复核；否则 `BLOCKED` |
| 发布前评测 | 冻结的候选版本和有版本的评测资产 | Run ID、模型/Prompt/数据/judge 版本、配置、样本数、原始报告引用、成本、失败与不确定性 | 所有必需标准均有当前证据；否则为 `NOT_RUN`、`UNKNOWN`、`STALE` 或 `BLOCKED` |
| 发布门禁 | 评测证据与发布范围 | 门禁表、置信/flake 限制、例外、剩余风险、人工决策人 | 建议由证据支持；正式决定在授权人批准前保持 `PENDING` |
| 灰度或影子 | 已批准的灰度计划和生产负责人 | 人群、流量比例、观察窗口、有来源的护栏阈值、隔离方式、停止条件 | 扩量/保持/回滚标准和证据采集方式明确 |
| 监控、回滚与收口 | 线上监控负责人和回滚路径 | 漂移/质量/拒答/反馈/成本信号、告警责任人、回滚记录、发布后评测和跟进 | 继续、保持、回滚或收口有证据记录；缺失信号不得视为健康 |

## 状态与版本规则

- 证据与门禁状态使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`、`UNKNOWN` 或 `STALE`。阶段执行可使用 `SKIPPED`，但必须说明原因。
- 人工发布决定使用 `PENDING`、`APPROVED` 或 `REJECTED`；只有有权限的人可以标记 `APPROVED`。
- 仅当所有必需标准都有当前且适用的证据时，门禁才可为 `PASS`。已知未运行时标 `NOT_RUN`，无法确认时标 `UNKNOWN`；缺少关键输入或存在不安全条件时标 `BLOCKED`；版本不匹配时标 `STALE`。
- 模型、供应商、模型版本、Prompt、数据集、judge、服务配置或灰度人群变化后，重新评估受影响的门禁。
- 保留原始评测报告引用、可用时的哈希、时间戳、样本数、不确定性和成本依据。摘要不能替代原始证据。

## 阶段交接

数据集/judge/统计协议交给 `llm-evaluation-design`；阈值与阻断规则交给 `quality-gate-design`；通用 T 窗口和发布协调交给 `release-testing-workflow`；受控生产观察交给 `production-verification`。不得把它们变成安装依赖，也不得在没有证据时声称其已运行。

## 输出

1. 特性和发布范围、负责人、版本映射。
2. 阶段看板：进入证据、负责人、状态、退出标准和交接。
3. 评测门禁表：`evaluation_gate_status`、阈值、观测值、原始证据、不确定性和成本。
4. 灰度/影子计划：`rollout_status`、人群、窗口、护栏、停止与回滚标准。
5. 监控与收口计划，包括证据缺口和下一步。
6. `human_release_decision` 与授权人；没有批准记录时保持 `PENDING`。

## 停止规则

- 若范围、负责人或回滚权限未知且会改变风险，阻断灰度计划。
- 必需门禁失败、阻断、过期或未运行时，不建议扩量。
- 监控信号缺失或失效不等于通过；按有来源的护栏保持或停止。
- 不得编造阈值、运行结果、批准或线上健康结论。

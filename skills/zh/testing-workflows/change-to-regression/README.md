# 变更到回归工作流

编码前可提供拟议变更和现有用例，调用 `change-to-regression` 生成候选护栏；编码后提供 Diff、Commit SHA、业务路径和回归清单，形成有依据的回归选择。

## 示例

> 比较当前分支和 `main`，为支付重试改动选择必测/可延后检查，说明风险和未覆盖路径；不要运行测试。

> 我准备调整折扣叠加规则，还未开始编码。根据这些现有用例列出需要保持的行为、候选护栏和编码后最小验证；把影响标为假设，不要运行测试。

## 最佳实践

编码前描述目标行为和现有约束；编码后提供精确 base/head SHA、完整 Diff、测试耗时和环境限制；实际运行后附时间、Commit 和运行记录。

## FAQ

- 对已实现变更，没有 Diff 或可检查来源时，精确影响保持 `UNKNOWN`；拟议变更可走 `PRE_CHANGE` 并标记假设。
- 不默认执行回归；计划不能写成通过结果。
- Commit 更新后旧 Checkpoint 标 `STALE`，重审相关范围。

# UX 质量视角：测试策略

## 输入

- `stage: test-strategy`
- 测试策略草案，以及可追溯的 UI/UX 需求、原型、流程、设计规范或历史体验风险。

## 适用性判断

先确认策略范围含有可追溯的 UI/UX 影响或体验证据。若材料仅为后端、基础设施或无 UI 影响的范围，输出“**不适用**”，写明原因、已知事实、缺口和需要何种 UI/流程/状态证据后才能重评；不要生成 UX 覆盖发现。

## UX 问题

- 策略是否覆盖已证实的任务流、信息架构、关键状态、一致性、响应式和无障碍风险？
- 设备、断点、输入方式、辅助技术和视觉状态的选择是否有证据基础？
- 进入/退出标准、可观察信号、责任和风险优先级是否能支持体验决策？

## 输出合同

输出：**摘要、事实、证据、发现、风险、信息缺口、待确认问题、行动、信心等级**。仅把提供材料支持的体验风险列为发现；将未提供的覆盖维度列为缺口。

## 证据与边界

- 不由通用平台假设推导本项目的断点、屏幕、读屏行为或通过标准。
- 不替代测试执行，不声称覆盖已实现、测试已通过或可以发布。

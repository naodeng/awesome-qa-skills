# UX 质量视角：测试用例编写

## 输入

- `stage: test-case-writing`
- 需转化为用例的 UI/UX 需求、原型、用户流程、状态定义、设计规范或已有用例上下文。

## 适用性判断

先确认材料有可追溯的 UI/UX 影响和足以描述的用户任务或状态。若仅有后端范围，或没有可验证的 UI/流程/状态证据，输出“**不适用**”，写明原因、事实、缺口和需补材料；不要编造测试步骤、页面、控件或预期结果。

## UX 问题

- 已提供的任务、导航、层级、状态、反馈、一致性、响应式或无障碍要求可转化为何种证据驱动用例？
- 哪些前置条件、设备/输入方式、辅助技术、数据或可观察结果已被材料支持？
- 哪些缺口会使预期结果不可验证？

## 输出合同

输出：**摘要、事实、证据、建议用例/发现、风险、信息缺口、待确认问题、行动、信心等级**。用例仅包含证据支持的前置条件、步骤和预期；每项风险和行动有优先级及责任角色。

## 证据与边界

- 不编造页面、控件名称、文案、错误状态、断点、读屏行为或结果。
- 不声称用例已执行、实现已正确或体验已验收。

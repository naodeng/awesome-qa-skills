# UX 质量视角：测试策略评审

## 输入

- `stage: test-strategy-review`
- 待评审策略及其关联的 UI/UX 需求、原型、流程、设计规范或体验风险证据。

## 适用性判断

先确认策略或关联材料可识别 UI/UX 影响。若没有，输出“**不适用**”，说明原因、事实、缺口和需补充的 UX 范围或证据；不要把通用 UX 清单写成评审发现。

## UX 问题

- 策略是否可追溯到已提供的导航、层级、状态、交互、一致性、响应式或无障碍证据？
- 是否遗漏有证据支持的高风险任务、状态、设备或辅助技术？
- 范围、方法、准入条件、证据产物与责任是否足以支持体验风险关闭？

## 输出合同

输出：**摘要、事实、证据、发现、风险、信息缺口、待确认问题、行动、信心等级**；发现针对策略与证据之间可证明的遗漏或不一致，行动指定责任角色。

## 证据与边界

- 不凭空断言某屏幕、断点、读屏路径或测试方式必须存在。
- 不评判实现正确或测试结果；只说明策略需补的 UX 证据。

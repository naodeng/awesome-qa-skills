# UX 质量视角：测试报告评审

## 输入

- `stage: test-report-review`
- 测试报告、体验观察、缺陷、截图/录屏及关联 UI/UX 需求、原型或流程。

## 适用性判断

先确认报告或关联材料包含可评审的 UI/UX 证据。若没有，输出“**不适用**”，说明原因、事实、缺口和需要的体验报告或关联材料；不要填充发现。

## UX 问题

- 报告结论是否有对应的 UI/流程/状态、设备、输入方式或辅助技术证据？
- 已观察问题的影响、范围、复现条件、风险和行动是否清楚？
- 哪些未测状态、设备或无障碍路径被错误地暗示为已覆盖？

## 输出合同

输出：**摘要、事实、证据、发现、风险、信息缺口、待确认问题、行动、信心等级**。指出可证明的证据不足、范围歧义或体验风险，行动分配给明确角色。

## 证据与边界

- 单一截图或结论只能支撑其可见范围；不能外推到移动端、键盘、读屏或全部状态。
- 不替代后端/API、安全或测试执行评估；不得断言实现正确、测试通过或可以发布。

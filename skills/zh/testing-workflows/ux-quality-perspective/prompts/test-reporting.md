# UX 质量视角：测试报告

## 输入

- `stage: test-reporting`
- 可追溯的 UX 测试记录、观察结果、缺陷、截图/录屏或与 UI/UX 影响相关的报告材料。

## 适用性判断

先确认材料含有 UI/UX 影响或体验测试证据。若仅有后端、性能或基础设施结果，且无界面/流程/无障碍影响证据，输出“**不适用**”，说明原因、事实、缺口和需要的 UX 记录；不要生成体验结论。

## UX 问题

- 记录能支持哪些已观察到的信息架构、状态、交互、一致性、响应式或无障碍结论？
- 证据覆盖哪些任务、设备、输入方式和辅助技术，哪些仍未知？
- 风险、影响范围、复现条件、责任和下一步是否可追溯？

## 输出合同

输出：**摘要、事实、证据、发现、风险、信息缺口、待确认问题、行动、信心等级**。报告只陈述记录支持的观察，不把未测维度写成通过。

## 证据与边界

- 不从单一截图或局部记录推断所有设备、状态或辅助技术均通过。
- 不断言后端实现、API 可靠性、安全、全量测试或发布结论。

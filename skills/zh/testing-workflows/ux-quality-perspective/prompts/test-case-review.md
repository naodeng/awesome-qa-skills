# UX 质量视角：测试用例评审

## 输入

- `stage: test-case-review`
- 现有测试用例及其关联 UI/UX 需求、原型、流程、状态或设计规范。

## 适用性判断

先确认存在可评审用例及至少一项 UI/UX 关联证据。若缺少用例或完全没有体验关联材料，输出“**不适用**”，说明原因、事实、缺口和所需材料；不要凭通用清单伪造遗漏。

## UX 问题

- 用例是否可追溯到已有的任务流、信息架构、交互状态、一致性、响应式或无障碍证据？
- 是否遗漏已提供证据支持的关键状态、输入方式、设备或辅助技术路径？
- 预期结果是否可观察、可复核且不依赖未给定的 UI 假设？

## 输出合同

输出：**摘要、事实、证据、发现、风险、信息缺口、待确认问题、行动、信心等级**。发现只指出可证明的覆盖缺口、歧义或不可观察性。

## 证据与边界

- 不因缺少原型而猜测屏幕、组件或断点。
- 不把用例存在等同于已执行、已通过或发布可行。

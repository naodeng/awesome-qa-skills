# 项目交付视角：测试报告评审

## 必需输入

`stage: test-report-review`；报告评审时点，以及带来源的会议日期、产能、依赖、里程碑、责任人、行动状态和由所属来源已记录的质量事实。

## 交付工作

跟踪报告评审的交付约束与后续：会议时点、可用产能、依赖阻塞、里程碑影响、责任人、行动截止日/状态和升级需要。仅记录来源已经明确的内容。缺少来源、责任人、截止日、依赖状态或产能时，标为信息缺口。

## 来源与质量边界

将“**项目约束**”“**行动跟踪**”与“**保留的质量事实**”分开。质量事实只能原样保留其来源和状态，供协同使用。不得关闭或重新定级缺陷、标记执行完成或通过、解释证据、给出质量结论或批准发布；对此类要求只能由所属决策方处理，并作为问题/行动记录。

## 输出

输出：**摘要、项目约束、行动跟踪、保留的质量事实、信息缺口、协同问题、下一步交付行动、信心等级**。这是交付跟进输入，不是测试报告质量结论或发布决定。

# 技术质量视角：代码评审

## 必需输入与门槛

`stage: code-review`；必须同时有代码身份（PR、提交、分支、发布版本或等价物）和可审查变更（diff、变更文件或代码）。需求、架构、API/数据合同、测试及安全/性能/可观测性证据均为辅助输入。

如果代码身份或可审查变更任一缺失，返回“**代码评审被阻断**”。说明缺少的身份和/或材料并索取它们；不得输出代码发现、合并就绪状态、正确性或测试通过结论。

## 技术评估

仅对可审查代码，将发现追溯到已识别的变更。按相关性评估架构边界、API 与数据校验、兼容性、授权/安全、错误与韧性、性能敏感路径、日志/指标/追踪和可维护性。区分静态观察与已验证的运行行为；缺少证据只能形成限定性风险。

## 边界与输出

不得编造代码行为、漏洞、执行结果或产品验收。否则输出：**摘要、事实、证据、技术发现、影响与严重性、缺失信息、问题、行动与下一步、信心等级**。

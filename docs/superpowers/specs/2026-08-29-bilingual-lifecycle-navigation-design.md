# 双语生命周期导航设计

## 决策摘要

项目继续使用稳定的物理目录，同时增加两层逻辑导航：

```text
能力演进层：Core QA Skills → Engineering QA Skills → Production Quality Skills → AI Native QA Skills
研发测试阶段：需求发现 → 方案设计 → 开发集成 → 测试准备 → 测试执行 → 发布交付 → 生产运行 → 复盘改进
```

README、路线图、索引与语言入口使用同一套映射。中文是默认入口，所有维护型项目文档均提供英文镜像和双向语言切换。

## 目标

- 在根 README 中完整展示 78 个单语 Skill，而不是只展示旧的 36 个测试类型。
- 先按四个能力演进层导航，再在每层下按研发与测试阶段细分。
- 每个 Skill 设置一个主要归属，跨阶段关系只作为辅助标签，避免重复计数。
- 让根文档、`docs/`、语言索引和 Skill 镜像遵循可自动检查的双语规则。
- 保持所有 Skill 目录、安装路径和名称不变。

## 导航模型

### 第一层：能力演进

1. **Core QA Skills**：建立需求、策略、用例、执行、缺陷和报告的基础闭环。
2. **Engineering QA Skills**：把质量前移到需求、代码、契约、回归和性能工程。
3. **Production Quality Skills**：基于发布、生产与可观测性证据做质量决策。
4. **AI Native QA Skills**：验证 AI 功能、LLM、Prompt、Agent、工具调用和安全边界。

`skill-engineering` 继续作为横向治理层；工作流继续作为跨阶段编排层；两者不计为第五个能力演进层。

### 第二层：研发与测试阶段

每个能力层从以下阶段中选择适用项，不要求为没有真实 Skill 的组合建立空分类：

1. 需求发现与分析
2. 方案设计与测试策略
3. 开发与持续集成
4. 测试设计与准备
5. 测试执行与分析
6. 发布与交付
7. 生产运行与事故响应
8. 复盘与持续改进

### 主要归属规则

- 依据 Skill 的主要输入、核心决策和主要交付物确定唯一归属。
- 工具专项跟随其解决的测试活动，不单独形成第五类能力。
- Plus 版本跟随基础 Skill 的主要归属，并标注为增强版。
- `ai-assisted-testing` 属于横向 AI for QA，放在 Engineering QA 的测试执行支持阶段，并明确区别于 Testing for AI。
- `root-cause-analysis` 主要归入 Engineering QA 的复盘改进；生产事故可从 Production Quality 链接调用，但不重复列入统计。

## README 信息架构

中文 `README.md` 是默认入口，英文 `README_EN.md` 是完整镜像。两者按以下顺序组织：

1. 语言切换、项目定位与准确统计
2. 四阶段演进图和使用说明
3. 工作流：说明如何跨研发测试阶段编排
4. 四个能力层，每层按适用的研发测试阶段列出 Skill
5. Skill Engineering 横向治理层
6. 安装、目录、质量门禁与贡献入口

每个 Skill 表格至少包含名称、目录和适用场景；统计必须满足每种语言 78 个、双语 156 个目录，并且每个 Skill 在主分类中只出现一次。

## 双语文档规则

### 根目录与 `docs/`

- 中文主文档：`NAME.md`
- 英文镜像：`NAME_EN.md`
- 两份文档顶部均提供相对路径语言切换。
- README、贡献指南、FAQ、索引、路线图、目录指南、编写规范、风格指南、审计报告、设计文档和实施计划均纳入检查。

### Skill 文档

- `skills/zh/` 与 `skills/en/` 使用相同相对路径表达语言镜像。
- Skill 内不增加 `_EN` 文件，也不要求逐文件放置语言切换；中英文通过 `skills/zh` 与 `skills/en` 相同相对路径形成镜像。
- 对只存在于单语言目录的维护型 Markdown，优先补齐镜像；语言专属示例可以保留，但必须从其 Skill 入口说明适用语言。

### 明确排除

- `legacy-prompts/` 历史兼容内容
- 外部资料快照和生成产物
- 第三方许可文本
- `.git`、评测运行产物和临时工作区

这些内容不要求逐文件翻译，但其正式替代入口或语言状态必须在维护型文档中说明。

## 自动校验

新增文档配对检查并接入主质量门禁，至少验证：

- 中文主文档与 `_EN` 镜像均存在。
- 项目级文档两侧包含有效的双向切换链接；Skill 内部文档仅检查相对路径镜像。
- `skills/zh` 与 `skills/en` 的维护型 Markdown 相对路径对齐。
- README 中 Skill 主分类无遗漏、无重复，数量与实际目录一致。
- Markdown 相对链接不存在明显断链。

## 验收标准

- README 中 65 个测试类型全部进入“四层能力体系 × 研发测试阶段”分类。
- 10 个工作流和 3 个 Skill Engineering 有独立且清晰的横向定位。
- 中文是 GitHub 默认入口，任何核心维护文档均可一键切换到英文并返回。
- 路线图、索引和语言分区 README 与根 README 使用相同分类口径。
- 双语配对校验和 `bash scripts/check_skills_quality.sh` 全部通过。
- 不移动目录，不破坏安装路径，不混入与本任务无关的工作区改动。

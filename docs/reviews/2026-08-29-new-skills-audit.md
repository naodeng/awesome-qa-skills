# 新增 QA Skills 审计报告

**日期：** 2026-08-29

**审计范围：** `explore` 分支相对 `main` 新增的 29 个 Skill，共 58 个中英文 Skill 包
**审计方法：** `skill-review` 九阶段审计，结合仓库 `SKILL_AUTHORING.md`、`SKILL_STYLE_GUIDE.md` 与全量质量门禁

## 执行摘要

**结果：** 修复后通过

- Critical：0
- High：3 类
- Medium：2 类
- Low：1 类

本轮没有依赖外部 API、SDK 或版本化代码示例，因此官方 API 与依赖版本漂移检查不适用。主要风险来自内容过短、跨文件契约不完整以及评测用例无法证明领域能力。

## 主要发现与修复

### High：Skill 入口是空壳

**证据：** 58 个新增 `SKILL.md` 均只有 6 行，只指向 Prompt，没有执行流程、按需加载、交付检查和常见误区。

**影响：** Skill 被触发后缺少稳定执行边界，无法保证信息不完整、生产操作或证据不足时的行为。

**修复：** 所有入口统一补齐何时使用、输出格式、使用流程、参考文件、核心约束、交付自检、常见误区和最佳实践，并保留每个领域的专属边界。

### High：主 Prompt 缺少可执行契约

**证据：** 48 个新增 Prompt 少于 10 行，其中 40 个只有 2 行；其余部分 Prompt 也未完整符合仓库规定的八段结构。

**影响：** 输出容易退化为泛化清单，缺少输入审计、失败模型、可验证断言、风险排序和结论边界。

**修复：** 58 个 Prompt 均重建为完整执行规范，并针对 29 个领域分别定义：

- 真实输入来源
- 领域分析维度
- 专属执行规则
- 最低覆盖清单
- 领域交付物
- 阻塞、停止、回滚或人工接管边界
- 事实、假设、信息缺口和证据要求

### High：评测用例模板化，不能证明领域能力

**证据：** 每个 Skill 虽有三类用例，但成功、缺失信息和风险优先级场景大量复用同一电商订单、积分兑换和功能列表输入。

**影响：** YAML 校验通过仍无法发现 Prompt 与 Skill 的领域能力缺失。

**修复：** 174 个中英文评测用例全部替换为对应领域场景，分别验证：

- 完整上下文下的领域产出
- 信息不完整时的受限初版
- 时间或权限受限时的风险取舍与安全边界

### Medium：中英文内容形式对齐但深度不足

**修复：** 保持目录名、frontmatter、章节顺序和评测意图一致，同时使用各语言自然表达，不做逐字机械翻译。

### Medium：生产与 AI Native 场景安全边界不完整

**修复：** 补充最小权限、脱敏数据、mock、dry-run、隔离环境、停止条件、人工接管和副作用验证要求；未授权时不执行真实生产写操作。

### Low：输出命名与结构不统一

**修复：** 统一任务理解、输入审计、风险优先级、核心执行项、剩余风险和下一步的顺序，同时保留领域专属交付物。

## 剩余风险

- 本轮运行了全部静态质量门禁和 skill-up YAML 校验，但没有为 174 个用例逐个调用模型执行语义评测；模型级回归仍可能受引擎、模型版本和随机性影响。
- 领域 Prompt 已显著增强，但后续应从真实使用反馈中补充失败样本，并把发现的回归固化进对应 `evals/cases/`。

## 结论

新增 Skill 已从“目录和元数据齐全”提升为“入口可执行、Prompt 有领域契约、评测能覆盖领域行为”。当前状态满足仓库提交前质量门槛，可进入 PR 评审。
